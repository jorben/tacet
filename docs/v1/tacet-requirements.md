## 1. 产品目标与需求边界

### 1.1 已确认的核心需求

| 编号 | 要求 | 验收含义 |
| --- | --- | --- |
| CORE-01 | 本地执行 | 文档解析、OCR、模型推理、脱敏、验证均在本机完成；预装所需资源后可断网运行 |
| CORE-02 | 基于语言模型识别隐私 | 利用专用敏感信息检测模型识别具有上下文含义的敏感片段，并允许规则补充 |
| CORE-03 | 支持常见文档格式 | 覆盖常见文本、办公文档、PDF 等；逐项声明读取、输出及隐藏内容处理能力 |
| CORE-04 | 文件类型可按插件扩展 | 增加格式无需修改核心调度及检测流程；插件协议有版本、能力声明和验收要求；MVP 支持第三方插件以 git 仓库或本地路径安装、启用、停用和卸载，见 3.7 节 |
| CORE-05 | 支持百兆字节级大文件 | 办公文档的体积多由图片和页数构成，按文件体积、页数、内嵌图片数、文本量及解压体积分别声明上限；在上限内完成处理并保持界面响应，超限时可控终止并说明原因 |
| CORE-06 | 不拖死机器 | 对解析、OCR、推理、预览、导出、验证全流程设置资源预算，并支持取消与恢复 |
| CORE-07 | 大批量任务可完成 | 通过预先授权的策略、分组操作和例外复核完成大量文件及高密度命中的任务；不要求逐文件弹窗或逐实体确认，并验证人工耗时与操作负担 |

### 1.2 建议的产品定位

面向需要在文档外发、提交、归档或交给其他系统之前移除敏感信息的个人与组织，提供本地检测、结果复核、格式专属脱敏、输出验证的一体化工具。主用户为中文办公外发：以 DOCX、PDF 等办公文档为核心，一次处理单份至数百份文档，重视定位复核（PDF 按页，DOCX 按页码与章节段落）、版式损失提示与可分享副本；优先考虑中文、英文和中英混排。CSV、JSONL、日志等数据在进入其他系统前的清理为次要场景，复用同一内核与字段策略，但不主导首版的规模指标与交互设计。

以桌面图形界面为主要入口，并提供共用同一内核、判定一致的 CLI（3.6 节）。首发操作系统为 macOS（arm64）与 Windows（x64）。格式、检测、OCR 与验证能力以插件扩展，除内建插件外支持安装第三方插件（3.7 节）。技术基线（Go + Wails v3、Python 进程外插件、语言无关的插件协议）见架构文档第 1 节；前端框架定为 React + TypeScript。

Tacet 主体以 Apache-2.0 开源，插件 SDK 与协议 Schema 同样采用 Apache-2.0；插件可单独发布并自选许可，并为将来可能的商业版保留授权空间，详见第 8 节。

### 1.3 术语与承诺

| 术语 | 本文定义 |
| --- | --- |
| 敏感片段 | 文本或图像中需要按策略处理的一段内容，包含类型、位置和检测来源 |
| 涂抹（遮盖 / 删除） | 从输出文件中真正去除相应内容或像素；只有显示遮挡不算完成。界面对所有去除操作统一称“涂抹”，由格式插件执行为文字删除、像素涂除或部件整体移除；呈现为色块还是类型占位符由方案设定 |
| 替换 / 假名化 | 将原值替换为占位符或其他值；可能保留关联性，也可能通过映射恢复 |
| 匿名化 | 需要进一步评估再识别风险，不能仅由片段删除或姓名替换自动推导 |
| 覆盖范围 | 对内容部件分别记录检查状态、输出处置和验证状态；明确哪些内容已检查、已移除、保留但未检查或处理失败 |
| 保真 | 保留约定范围内的非敏感内容、结构和版式；不同格式有不同验收标准 |
| 处理单元 | 可以分批处理的页、段落、单元格组、记录或文本片段 |
| 单文件任务 / 批次 | 单文件任务拥有独立输入、复核、导出和验证状态；批次汇总一组已冻结成员的任务、共享策略及逐文件结果 |
| 自动解决 / 人工复核 | 自动解决是执行用户事先授权的确定策略；人工复核可逐项或按明确范围批量决定，两者分别留痕 |
| 阻塞项 | 当前策略无法安全决定或执行的例外，如冲突、位置不可靠、类型约束或未检查部件；与全部候选命中数分开统计 |

### 1.4 通用约束

以下约束适用于全部功能、格式、插件（含第三方插件）与处理阶段，在此一处定义；其他章节及架构文档以编号引用，不再复述。不能以“格式不支持”或“插件未实现”为由豁免。

| 编号 | 约束 | 定义 |
| --- | --- | --- |
| INV-01 | 如实报告范围 | 报告实际处理范围、剩余不确定性与人工复核状态。不得把“没有检出”表示为“没有敏感信息”，不得把验证通过表示为全部敏感信息均已识别；自动解决、人工逐项决定、人工批量决定与抽查分别统计，后两者不得表述为逐项人工审阅 |
| INV-02 | 未完成不等于零命中 | 任何必需阶段（部件枚举、抽取、OCR、规则编译与匹配、模型推理、回写、验证等）因失败、超时、超限、取消、资源缺失或不支持而未完成时，记为失败、阻塞或覆盖缺口；不得当作零命中或完整成功，不得截断或跳过余下内容后仍宣称全量检查 |
| INV-03 | 不静默变更 | 任务以不可变快照绑定成员、配置、授权及模型、规则、插件、运行时版本；重试、恢复、升级、后端异常或资源缺失均不得静默改变快照、扩大授权或切换模型；需要变更时创建新版本并明示影响 |
| INV-04 | 版本绑定与依赖失效 | 检测结果、复核决定、操作计划、候选输出、验证结果及发布授权均绑定输入指纹及其依赖的版本；上游任一版本变化时，依赖它的下游结果失效，不得沿用旧验证或旧授权发布。原有人工决定只在内容、位置及授权范围重新核对一致后复用；同值出现在新位置不自动继承 |
| INV-05 | 全流程有界资源 | 解析、部件枚举、OCR、推理、规则、预览、导出、验证、查询及批量操作均受内存、CPU、磁盘、并发与时间预算约束，支持背压与取消；不得无界预读，不得把全量文档、结果或成员一次装入内存或界面；预算覆盖整个应用进程树及批次累计占用 |
| INV-06 | 离线与不外传 | 预装资源后，文档处理全程可断网完成；文档、敏感值、指纹、文件名及路径不上传，默认无遥测；缺少资源时明确阻塞，不自动下载、安装或改用云端；资源下载、更新及插件安装与文档处理分离 |
| INV-07 | 敏感数据保护 | 原值、中间数据、映射、索引、候选输出及恢复数据按敏感数据加密存储、受配额约束并按授权清理（第 7 节）；日志、公开报告、诊断及 CLI 输出默认不含原值、文档片段、完整路径、密码或替换映射 |
| INV-08 | 不执行不受信任内容 | 文档、元数据及插件返回内容均作为不受信任数据：不执行宏、脚本、外部链接或嵌入程序，不自动访问外部资源，不获得应用桥接或宿主权限 |
| INV-09 | 位置不可靠即不猜测 | 删除、替换及关联都须有可靠的源位置；找不到可靠映射时进入复核或失败，不按偏移差、长度差或值相同推断位置 |

### 1.5 首版不承诺的能力

- 所有行业、语言和文档上零漏检，或自动达到法律意义上的匿名化。
- 任意复杂 Office 文件均可无损编辑；数字签名在修改后仍保持有效。
- 未安装模型时自动调用云端替代，或将文档上传外部服务。
- 默认执行文档宏、脚本、外部链接或嵌入对象中的程序。
- 首版自动识别人脸、签名图样、二维码及图像中的所有视觉隐私；这些需独立检测插件及覆盖说明。
- 首版 PDF 输出保留原文本层、可搜索性、链接、表单及矢量版式；MVP 默认输出栅格化安全 PDF，保留结构的 PDF 删除列入 M2，见 4.1 节。
- 通过 Mac App Store 分发：MVP 支持安装第三方插件，与其审核指南 2.5.2 冲突；macOS 版采用 Developer ID 签名并公证后自行分发。
- 多个内置模型或导入用户自备的模型权重：MVP 只内置一个检测模型（AstrLink Guard）并配合规则使用；第二个内置模型作为可选模型资源包列入 M2，见架构文档 8.2 节。

### 1.6 产品名称与命名缘由

产品英文名称确定为 **Tacet**。

Tacet 是音乐术语，表示某个乐器或声部在指定段落中保持沉默。它表达的是对特定部分有意识的留白，同时让作品的其他声部继续演奏。

这一含义与产品的选择性脱敏相呼应：一份文档如同一段乐谱，涉及隐私的内容如同需要保持沉默的声部。Tacet 根据策略隐去敏感部分，尽可能保留其余内容的表达、结构与使用价值，使文档能够在保护隐私的前提下继续流通。

> 让敏感的部分保持沉默，让其余内容继续表达。

Tacet 名称简短，寓意含蓄，传达安静、克制、精确的产品气质；其含义也能自然延伸到文本、表格、图像和其他文档形式。

## 2. 用户场景与主要流程

### 2.1 典型场景

| 场景 | 定位 | 输入 | 期望结果 |
| --- | --- | --- | --- |
| 文档外发 | 主场景 | 单份或少量合同、简历、客户材料等 DOCX / PDF | 识别人名、联系方式等，PDF 按页、DOCX 按页码与章节段落复核后导出可分享副本；常用路径操作少（FR-28、UX-00） |
| 大批量外发准备 | 主场景 | 数十至数百份办公文档，累计数千至数万候选命中 | 先确认一份批次策略，再集中解决例外；合格文件可先完成，最终清单能核对交付范围 |
| 大型办公文档 | 主场景 | 100 MiB 级、数百至上千页、含大量图片的 PDF / DOCX | 显示阶段进度，可取消、暂停、恢复，内存不随页数持续增长 |
| 表格交付 | 主场景（XLSX 值子集待 M0 准入） | 客户清单、员工表、交易资料等 XLSX / CSV | 依据字段与上下文识别敏感数据，保留约定表格结构 |
| 扫描材料处理 | 后续（P1） | 扫描 PDF、PNG、JPEG | OCR 检测并移除对应像素，提示低质量及未识别区域 |
| 数据进入其他系统前清理 | 次要场景 | TXT、Markdown、日志、JSONL、CSV | 批量处理，保持数据结构；同一批次的实体一致替换见 FR-16（P1）；数百 MiB 级日志建议使用仅规则 / 整字段模式（FR-18） |

### 2.2 主流程

1. 取得工作区所有权后导入文件或批量任务，识别实际格式，检查权限、加密、结构和资源需求，在预算内逐步建立完整部件清单。
2. 选择脱敏策略、输出形式、模型及资源档位；批量任务一次确认自动处理范围、人工介入条件、发布方式和恢复数据期限，展示已知不支持内容。
3. 分批解析；有需要时执行 OCR，建立可回写的原始位置映射。
4. 运行规则与模型检测，合并冲突，持久化命中及覆盖状态。
5. 先展示自动解决、待复核、覆盖缺口及可交付文件数；用户按字段、类型或上下文分组复核例外，必要时查看原文、补充遗漏或排除误报。
6. 逐文件生成脱敏操作计划，在受保护的私有工作区生成候选输出，记录输出位置与输入 / 操作的关联，完成隐藏内容清理。
7. 重新打开输出，核对部件去向、文件可读性、目标内容移除及覆盖范围；新风险按候选版本关联回原文或明确阻塞。
8. 发布最终输出和不含原始敏感值的处理报告，按策略清理中间数据。

单文件检测完成即可进入复核，不以整个批次检测结束为前提，其他文件继续处理；首版无需支持一边检测一边修改同一文件。复核或策略变更按 INV-04 使受影响的导出、验证及未发布结果失效。

单个或少量文件走快捷路径（FR-28）：步骤 2、5、8 合并为少量界面操作，内部仍作为批次执行全部阶段并遵守全部约束。

### 2.3 大批量任务的完成原则

- 开始前集中确认策略，处理中集中处理例外，全部成员结束后进入结果页；交付清单是按需查看的核对工具，不是必经步骤。默认避免逐文件弹窗、重复选择模型和反复确认相同操作。
- 复核入口以“还需要做什么”为中心，展示阻塞原因、影响文件数、可采取的操作及其后果，而非一份持续增长的命中列表。
- 人工决定只有两类，用户无需理解内部阶段：针对某处内容（命中、图像、附件、未检查区域等）只在“涂抹”与“保留”之间选择；针对整个文件的阻塞只在一个解除动作（解锁，或处理失败时“重新处理”）与“跳过此文件”之间选择。系统能自行解决的情况（验证未完成、已涂抹内容仍有残留）不询问用户，规则见 3.4 节与 BUX-03。
- 减少人工负担依靠字段策略、确定的自动处理和可解释的分组，不能依靠截断候选或隐去覆盖缺口。方案的最低置信度（FR-11）是用户明示的检测范围设定，低于该值而未处理的候选单独计数并在摘要与报告中列出，不表述为没有敏感信息（INV-01）。
- 单个文件等待复核、密码或重试时，其他独立文件继续；资源不足时按预算暂停派发，不因部分异常重跑整个批次（BUX-12、BUX-14）。
- 同时衡量机器耗时和用户的有效操作时间；能打开海量结果表，不等于用户能完成海量复核。具体流程与验收见 3.5、5.5 和 9.3 节。

## 3. 功能需求

本文优先级均为建议范围：P0 为首版必备，P1 为后续增强，P2 为长期扩展。架构约束适用于所有阶段，不能为了新增格式绕过离线、资源和覆盖要求。

### 3.1 导入与任务管理

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-01 | P0 | 支持文件选择、拖放、多文件队列及显式文件清单导入；大批次无需重复逐个添加，清单中的路径按敏感数据管理；目录递归与文件过滤可列为 P1 |
| FR-02 | P0 | 联合扩展名、文件签名及结构探测实际格式；不支持、损坏、加密或超限均给出明确状态 |
| FR-03 | P0 | 源文件默认只读，输出到不同文件；检查符号链接、硬链接及路径别名，防止目标指向源文件；同名目标使用无覆盖发布，竞争创建时也不得静默覆盖 |
| FR-04 | P0 | 提供开始、排队、暂停、继续、取消、重试和任务清理；批量任务逐文件记录结果 |
| FR-05 | P0 | 暂停在可恢复的安全边界生效；取消默认“停止并清理”，另提供“停止并保留以便恢复”；进程故障检查点与跨应用恢复分开管理，按 7.1 节执行保留期限。恢复粒度为“文件 × 阶段”：已完成阶段的结果及已提交的复核决定持久化，未完成阶段从该阶段起点重做；只有声明大文件能力（PF-01）的格式插件须提供阶段内断点续跑 |
| FR-06 | P0 | 展示当前阶段、已处理页数 / 记录数 / 字节数、覆盖缺口和资源占用；总量未知时使用不确定进度 |
| FR-07 | P0 | 任务参数及模型、规则、插件与运行时版本形成不可变快照，重试与恢复沿用原快照（INV-03） |
| FR-08 | P0 | 输入被修改、替换、删除或移动时暂停并验证；不能继续把旧位置映射用于新内容 |
| FR-09 | P0 | 带打开密码的 DOCX 与文字型 PDF 在本地输入密码后处理；批量任务中逐文件输入，例外队列可一次列出整组。密码只用于本次解锁，不写入任务存储、日志、诊断、命令行参数、环境变量或配置；恢复与重新处理复用加密保存的解密副本，无需再次输入。密码错误可重输，不计入“重新处理”次数。输出不继承原件的加密与权限限制，导出前及报告中注明；不支持的加密方式在预检中明确标出。实现见架构文档 4.6 节 |

| 中国居民身份证号 | P0 | 模式、校验和上下文；校验失败但疑似敏感的结果可转入复核 |
| 银行卡、个人账号 | P0 | 规则、校验与模型；区分财务卡号、员工号、会员号等策略 |
| 密码、API Key、Token、Cookie、私钥 | P0 | 已知格式、字段上下文与模型组合；多行及跨块凭证需覆盖 |
| 个人日期 | P0 | 明确生日、证件日期、就诊日期等政策；提供“全部日期”规则选项 |

具体要求：

- FR-10（P0）：规则、词表、模型输出统一为敏感片段，保留来源、标签映射、原始分数及规则版本。
- FR-11（P0）：策略按类型定义检测开关、处理方式、保留字段与例外。使用模型的方案另设一个最低置信度：模型来源且分数低于该值的候选不纳入脱敏处理，不涂抹，也不进入例外与复核队列；规则、词表、校验器、整字段规则及人工补充的命中不受影响。低于阈值的候选单独计数，策略摘要、预检汇总与处理报告列出阈值及数量（INV-01）；复核中可按此筛选查看，用户选择涂抹即为人工决定。不得声称调整阈值能任意改变模型原生标签政策。
- FR-12（P0）：不同模型分数不得直接当作同一概率比较。最低置信度的取值范围与默认值随所选模型而定：默认值按模型、类别和业务数据校准（M0），同时作为低置信度提示的界线（FR-21）；方案改选模型时重置为新模型的默认值并提示，不沿用旧数值。阈值高于默认值时，依赖模型的类别不获得无人值守资格（6.2 节）。
- FR-13（P0）：检测阶段可以保留相互重叠的候选；导出前产生无歧义的操作计划，不因冲突静默丢弃高风险片段。
- FR-14（P0）：优先级为用户最终复核决定、明确策略规则、自动检测建议；策略禁止用户排除的场景另行定义权限。
- FR-15（P0）：明确排除项必须可追溯；为检测合成的表头 / 相邻段落上下文不能当作可回写正文或进入公开报告。源文件中的键名、表头本身若被策略命中，仍按其真实源位置与授权处理。
- FR-16（P1）：支持同一文档或同一批次的实体一致替换；别名合并需要可解释的依据，不能仅凭同名认定同一人。
- FR-17（P0）：支持按 CSV 列、JSON / JSONL 字段路径指定整字段处理，适用于字符串和数字；由用户明确授权处理该范围的全部值，无需逐值等待模型命中。字段直接处理与模型识别数量分别统计。
- FR-18（P0）：每个启用类别必须绑定可用检测来源及质量适用范围；模型标签缺失、专项规则缺失或配置不受支持时，明确阻塞或缩小策略（INV-02）：被缩小的类别列为范围外，不报告为已检查。在界面编辑规则组内的规则（启停、编辑、删除）会让使用该规则组的方案中已设为处理的类别失去检测来源时，保存前询问，经确认后才保存；回滚规则组或方案的历史版本、在方案中移除规则组、切换方案的检测方式或模型、修改模型标签映射都直接生效，不询问。失去来源的类别在方案中显示为关闭。运行预设可选择“仅规则 / 整字段”检测模式，供大日志及结构化数据使用：不调用模型，只依靠规则、词表、校验器及 FR-17 的整字段处理；依赖模型的类别（如人名、私人地址、无固定格式的凭证）须在策略摘要中明确列为范围外或经确认缩小，不得报告为已检查。
- FR-19（P0）：支持独立、版本化的模型配置、识别规则集、脱敏方案及组合它们的运行预设。MVP 只内置一个检测模型（AstrLink Guard），不支持导入权重；模型配置仍作为独立的版本化对象，为 M2 的可选模型资源包预留。用户可保存、复制、编辑、选择及导入 / 导出多套规则、方案与运行预设（导出内容不含模型权重）。界面与 CLI 共用配置校验，敏感词表和路径引用按 INV-07 保护。模型配置变化时检查类别、语言、后端及资源适用性；修改规则或处置按 INV-03、INV-04 处理，组合与失效规则见架构文档第 8 节。用户的规则集、方案与运行预设按以下规则管理版本；内建对象与规则包按应用或插件版本标识，不适用（FR-46）：
  - 版本号：格式为 `v{整数}`（如 `v3`）；新建、复制或导入的对象从 `v1` 开始。每保存一次且内容有变化时加 1；只改名称或备注，或保存时内容未变，不加版本。
  - 历史与回滚：每个对象保留最近 5 个版本，含当前版本，超出时清理最旧的版本。回滚把所选历史版本的内容复制为一个新版本保存，名称与备注保持当前值，不改写或删除其他版本。任务快照保存所用配置的完整内容，历史版本被清理不影响已开始的任务（INV-03）。
  - 引用：运行预设引用规则集与方案时始终跟随其最新版本，不锁定某一版；任务开始时才解析为具体版本并冻结到快照，之后的修改只作用于新任务。
  - 复制：复制出的规则集与方案和原对象（含内建对象与规则包）相互独立，原对象之后的更新不同步，也不提示。
  - 导入：导入对象与本地同类配置同名时提示冲突，不覆盖、不合并，由用户改名后导入或取消导入。
  - 不记录修改摘要；历史版本只显示版本号与保存时间。

部分掩码和一致替换降低暴露程度，但仍保留部分信息或关联性。策略界面和报告应准确说明其效果。占位符长度变化造成排版变化时，需要可预览，并按格式约束处理溢出。

### 3.4 输出与验证

- FR-30（P0）：候选输出先在受保护的私有工作区生成并验证，未验证文件不进入任何用户可见目录或外部程序（SEC-11）。验证通过后，把已验证的确切字节复制到目标卷中以最小权限、独占方式创建的临时文件，核对摘要后采用该文件系统支持的无覆盖原子发布方式；不支持时明确声明发布限制，不能声称有原子保证。
- FR-31（P0）：每次导出绑定输入指纹、操作计划版本和配置快照；复核结果或配置变化后按 INV-04 失效，旧验证不能沿用。
- FR-32（P0）：重新打开输出并检查格式完整性、已批准操作的执行结果和非敏感结构；不能只检查文件是否存在。
- FR-33（P0）：检查约定范围内的元数据、批注、修订、隐藏内容、附件、旧对象或缓存残留；格式插件必须建立输入部件清单并逐项记录输出去向，未知部件不能绕过覆盖报告直接复制；具体见 4.2 节。
- FR-34（P0）：分别验证已批准操作的预期效果和输出中的新增风险。残留判断绑定源位置、操作及允许保留的目标范围，不能仅凭全局原值搜索定成败；再次检测的新命中须按冻结策略解决或返回复核。不同解析器或 OCR 可作为增强检查，重复运行同一模型不能视作独立证明。
- FR-35（P0）：检测、回写或验证失败按 INV-02 处理。仅覆盖不完整但文件可读、已批准操作正确且必要输出验证通过的结果，可按独立授权发布为部分结果（复核中选择“保留”时已展示这一后果，该选择即构成相应范围的授权，见 4.2 节），使用可辨识的文件名及清单标记，并附未处理范围；回写错误、文件损坏或必要验证未完成的候选不得发布。CLI 必须使用区别于完整成功的退出状态。
- FR-36（P0）：生成 JSON 处理报告及可读摘要，含版本、策略摘要、统计、复核状态、覆盖范围、验证状态与错误码；默认不含敏感原值、源文件名和文件全路径。批次交付清单逐文件记录中性标识、输出相对位置、输出摘要和结果状态；含源路径的本地定位索引加密保存，不自动随输出分发。
- FR-37（P0）：发布前所有待复核项必须逐项或按明确范围批量确认、排除，或由预先授权的自动策略解决；各类决定按 INV-01 分别统计；无需把自动解决项再次逐条人工确认。

验证状态取值见 4.2 节，操作执行验证与新增风险检查分别记录。只有完成所有必要阶段且无覆盖缺口、无待复核项、验证通过并已发布的单文件任务，才能显示“已按策略完成”，并仍附自动识别局限说明（INV-01）。

验证产生的新命中绑定候选版本，经输出关联映射（架构文档第 5 节）回到原始输入位置或既有操作，再重新生成计划、导出和验证；人工保留决定的复用遵守 INV-04。无法可靠关联的命中进入例外队列：用户在匹配版本的原文中重定位、授权可可靠定位的保守范围处理，或按允许的策略明确保留；仍无法形成可执行计划时阻塞（INV-09）。不自动把候选当作新的输入，也不无限重新检测直至“无命中”或无提示放宽策略。批次内其他已满足条件的文件可继续发布。

**导出与验证失败的处置。** 遵循 2.3 节的原则：某处内容的问题由用户在“涂抹”与“保留”之间决定，只有整个文件处理失败才提供“重新处理”。

| 情况 | 验证状态 | 处置 |
| --- | --- | --- |
| 验证未完成：超时、工作进程异常、磁盘空间不足等 | `not_run` | 不询问用户。系统在重试预算内复用现有候选自动重跑验证；资源类条件按 BUX-03 解除后只重试受影响文件；超出预算按整个文件处理失败处置 |
| 验证发现新增风险 | 按新命中处理 | 不计为验证未通过；按上文规则关联回原文或既有操作，并入相应类别的复核分组并标注“导出后发现”，用户照常选择涂抹或保留 |
| 已涂抹的内容仍有残留（如号码末几位未被去除） | `failed` | 不询问用户：用户已决定涂抹，系统在同一文本单元、字段或图像区域内扩大涂抹范围，按 INV-04 形成新计划版本后重新导出并验证，每个文件限一次；扩大的范围计入自动处理摘要。仍有残留或需超出该范围时，按整个文件处理失败处置 |
| 回写失败、输出损坏、无法重新打开或部件去向核对不符 | `failed` | 整个文件处理失败 |

整个文件处理失败时，例外队列只提供“重新处理”与“跳过此文件”。重新处理沿用原快照（FR-07、INV-03）从失败阶段重做，可解决偶发的进程、资源或环境故障；确定性错误重做后结果相同，因此每个文件只提供一次，再次失败即标记为“无法处理”并附原因，不再提供选项。处理失败的文件不提供“仍然导出”或“作为部分结果发布”（FR-35）；已跳过与无法处理的文件计入未交付范围（BUX-12）。

已验证但未授权发布的文件显示“待发布”，与“已交付”区分。文件发布后才提交其清单记录；崩溃后以输出摘要核对并补记。批次清单使用检查点及最终快照，可逐文件核对完成度，不把多文件发布宣称为一个原子事务。

### 3.4.1 首次模型准备与未就绪引导（P0）

- 首次打开直接进入首页，在导入区上方内联仅显示一句提示“请先下载隐私识别模型，以便支持更优识别效果和本地离线使用”，不另设标题，提供“前往下载”入口进入插件页；此处不展示所选模型、不提供全局模型选择；首页不重复说明模型配置与下载步骤。无需额外欢迎向导或强制弹窗。已下载匹配资源时，跳过下载并异步完成校验和试运行。
- 模型目录、下载状态、进度、错误和就绪检查均按模型 ID 与版本独立管理；首页只做通用资源准备引导，不根据首页方案显示“当前所选模型”，也不要求下载全部模型。模型选择仅属于各个方案，例如英文材料方案与中文材料方案可绑定不同模型；插件页只管理可用模型目录及下载 / 就绪状态，不设全局当前模型或使用中的方案选择。首发目录仅提供 AstrLink Guard；后续新增可选模型沿用相同流程，在方案中选择使用，下载本身不改变方案或正在等待 / 执行任务的模型绑定。多个模型的语言、检测类别、质量与资源适用范围分别声明，不把一个模型就绪视为所有模型就绪。
- 用户点击后才联网下载官方、与当前应用签名清单匹配的模型包。下载前检查空间，展示实际下载总量与所需空间（包含展开文件和临时副本）；下载量按完整性清单求和（包含外部权重、分词器与配置），不得只展示 ONNX 图或历史 INT8 权重的大小。下载、校验、加载与固定样例试运行分别显示状态；文件下载完成不代表模型就绪。已有可用模型且没有进行中的准备或需处理状态时，首页通用准备卡自动收起；顶栏模型入口仅在所有模型均待下载时显示，下载开始后隐藏；已有模型下载完成时不再显示，后续通过插件页管理。用户导入文档后，按任务方案检查它绑定的模型；未就绪时才在本次任务的准备卡中显示具体方案和模型，以及下载 / 修复入口。插件页将“模型”区块置于“格式”上方，每个模型分别展示名称、版本、语言、下载 / 就绪状态与对应下载、暂停、继续或重试操作；资源管理统一放在插件页。
- 下载期间可浏览方案及选择文件。单份文件在检测前保留本次选择；批量在预检页保留文件和设置。模型未就绪时，原位展示原因、修复入口和“取消本次操作”；准备好后启用“继续处理”，由用户明确继续，不自动处理已选文件。更换文件前须继续或取消已有等待操作，避免静默替换。取消等待操作不取消独立的模型下载。
- 下载支持暂停、断点续传与重启后继续；断网保留可续传部分并提供“继续下载”；空间不足说明释放空间后重试；文件校验失败不得加载，重新下载；校验通过但加载或试运行失败时，提供“重新准备”与重新下载。不提供模型离线包导入；尚未下载的模型需联网获取，已下载并通过检查的模型可断网使用。
- 新任务、批次开始、切换方案重新检测与恢复任务均检查其绑定模型；按 INV-03、INV-04 处理缺失或变化，不自动改为仅规则或云端。用户明确选择且满足 FR-18 的仅规则方案不依赖模型；模型下载、安装与文档处理互斥（SEC-03），已有网络活动须先停止才可开始文档处理。
- 原型提供首次使用、下载中、暂停、断网、空间不足、校验失败、加载与试运行、启动失败、已选文件等待及批量未就绪场景，全部仅模拟，不实际下载或安装；正式版体积与空间显示取发布清单。

### 3.5 大批量处理与复核体验（P0）

#### 3.5.1 批次准备与处理模式

| 模式 | 自动行为 | 人工介入与发布 |
| --- | --- | --- |
| 引导批量（默认） | 用户一次确认本批次策略后，系统自动检测并解决已授权处置；按资源预算逐文件导出、验证 | 集中复核例外，根据摘要一次授权按已批准计划发布；文件验证合格后陆续交付，无需逐文件确认 |
| 无人值守（显式启用） | 使用已保存且适用范围经过评测的策略，自动处理并发布符合条件的文件 | 遇到未授权例外时阻塞相应文件并继续其他文件；运行结束给出待处理清单，不弹出等待输入的窗口 |
| 严格复核（按需选择） | 检测、分组和预览自动完成，不自动替代要求人工决定的项目 | 人工可按经确认的字段、分组或单项复核；界面说明预计工作量 |

- BUX-01：开始前展示格式分布、预检异常、模型就绪情况、输出命名及同名冲突、空间预算、恢复期限、已知覆盖限制，以及图像 / 嵌入内容的默认处置与受影响数量（4.2 节）。批次成员、策略、输出方式及发布授权形成快照；新增文件作为明确的新批次或成员版本，不能悄悄进入已批准范围。
- BUX-02：内建“通用办公外发”初始策略默认对启用类别的候选执行完整删除或类型占位符，对已授权的整字段范围直接处理；达到最低置信度的候选按保守处置执行，标为低置信度的也不例外，用户可在发布前纠正误报；内建策略的最低置信度取所绑定模型的校准默认值（FR-12）。不得默认部分掩码、默认保留达到阈值的不确定命中，或按未经校准的统一分数决定安全性。格式不支持所选动作时提前提示并形成例外。页内图像、扫描页及嵌入内容的默认处置见 4.2 节。
- BUX-03：冲突且无法确定合并动作、位置不可靠、未获授权的类型 / 键名变更、必查部件未检查、整个文件处理失败（见 3.4 节；验证未完成与已涂抹内容残留由系统自动处理，不进入队列），以及当前策略要求人工决定的情况，进入集中例外队列。队列中针对某处内容的例外只提供“涂抹”与“保留”，针对整个文件的阻塞只提供一个解除动作与“跳过此文件”（2.3 节）；保留未检查内容将形成部分结果（FR-35），作为该选项的后果标注，不另设决定类型。相同原因的错误聚合说明，不产生数千个模态对话框。缺资源等可修复条件解决后，只重试受影响任务。
- BUX-04：已保存策略可复用于新批次；每次显示策略版本号、模型与格式适用范围及保存时间（FR-19）。系统升级或资源缺失按 INV-03 处理；未来文件适用的规则与本次批量决定必须区别展示。

#### 3.5.2 分组决定与范围控制

- BUX-05：支持按文件 / 模板结构、列或字段路径、敏感类别、检测来源、阻塞原因和处理动作分组；同值可作查找与批量选择依据，但不能认定同一实体，也不能将某处“公开信息可保留”外推到所有同值。分组应展示数量、涉及文件数、差异和代表性上下文，可下钻到全部成员。
- BUX-06：批量动作明确区分“当前页”“已选项目”和“当前筛选结果全部”，执行前给出确切数量与范围摘要。决定绑定已完成检测的结果版本及冻结成员集；后续新增命中不自动加入。支持一项决定覆盖跨页大量成员，不能要求逐页勾选。
- BUX-07：整列 / 字段动作可一次覆盖大量不同值；预览处理前后样例、空值和异常类型，以及对结构和数据用途的影响。自动应用保存的字段规则前校验字段路径、表头和类型等结构条件；模板不匹配转入例外，禁止仅凭相同列序号套用。
- BUX-08：批量保留 / 排除需明确依据和上下文范围，必需人工处理的例外不能被普通“全选确认”绕过。重复决定优先保留已确认的单项例外，替代既有决定时展示影响；批量操作支持撤销，已发布文件的处理见架构文档第 6 节。
- BUX-09：复核界面默认突出未解决阻塞项，同时可查看自动处理摘要、原文及输出差异。导出前的“效果”“对比”视图是按当前决定生成的模拟预览，界面须标明，以验证后的输出为准（架构文档 4.2 节）。支持查看未命中区域、补充遗漏和按风险抽查不同文件及部件；抽查是辅助措施，其结论按 INV-01 表述。
- BUX-10：分组查询、全选及批量提交在本地存储侧执行，使用有界分页与成员引用（INV-05）；长操作显示进度，提交与撤销具有事务语义，崩溃后不会把半次操作误认为全部生效。

#### 3.5.3 进度、恢复与交付

- BUX-11：批次总览分别显示机器处理进度、已自动解决命中数、人工待决项 / 分组数、覆盖缺口、待发布及已交付文件数。剩余机器时间给出估算范围，依据不足时不显示精确倒计时；人工剩余时间单列，未取得复核速率时只展示数量与可用批量动作。
- BUX-12：用户可调整未开始文件的顺序、暂停派发新文件，或只停止选定任务。已完成文件可先复核；选择“发布符合条件的文件”时授权范围绑定明确的成员与计划版本，后台可在预算内逐文件导出、验证并交付，不要求整个批次候选同时占盘。验证产生例外或计划改变的成员重新待决，其他成员继续；不得因此反复要求整批重新确认。界面始终显示“已交付 n / 总计 m，另有多少阻塞、失败或未处理”，不能用“批次完成”掩盖遗漏。
- BUX-13：复核决定及时持久化，显示保存状态；恢复后保留筛选、分组和复核位置，不重复询问已提交决定。保留与清理遵循 7.1 节，关闭窗口不静默丢弃待复核结果。
- BUX-14：只重试失败、阻塞条件已解除或用户选定的成员；整个文件处理失败的成员可由用户重新处理一次，再次失败即标记为无法处理（3.4 节）；已发布结果不重复生成、不追加重复计数。输出名称可预览且确定，默认使用不含敏感值的中性名称；名称冲突、空间不足、目标暂不可写集中处理，重试发布可复用仍有效的已验证输出。
- BUX-15：导出前摘要包括将发布文件数、自动 / 人工处理方式、保留例外、被整体移除的部件及剩余阻塞；用户无需打开每份报告才能确认交付范围。输出与部分结果明显区分，清单可核对遗漏；本地详细索引与可分享报告分开提供。
- BUX-16：批次内全部成员均已结束（已交付、部分结果、已跳过或无法处理），且没有待复核或待发布的成员时，界面自动进入结果页，不要求用户先打开清单。结果页显示已导出数与总数、导出位置，以及部分结果、已跳过和无法处理的数量；未全部导出时明确说明“未导出 n 份”，不得显示为全部完成（BUX-12、INV-01）。结果页只提供“打开导出文件夹”和“查看清单”两个入口；清单用于逐文件核对、导出与保存，从结果页按需进入并可返回。人工复核先于机器处理完成时，复核完成页说明仍在处理的数量，处理结束后同样进入结果页。
- BUX-16：批次内全部成员均已结束（已交付、部分结果、已跳过或无法处理），且没有待复核或待发布的成员时，界面自动进入结果页，不要求用户先打开清单。结果页显示已导出数与总数、导出位置，以及部分结果、已跳过和无法处理的数量；未全部导出时明确说明“未导出 n 份”，不得显示为全部完成（BUX-12、INV-01）。结果页只提供“打开导出文件夹”和“查看清单”两个入口；清单用于逐文件核对、导出与保存，从结果页按需进入并可返回。人工复核先于机器处理完成时，复核完成页说明仍在处理的数量，处理结束后同样进入结果页。

### 3.6 CLI 与非交互批量处理（P0）

- CLI 接收版本化策略和文件清单，提供预检、运行、状态 / 报告、列出未结束的批次、恢复、选定成员重试及清理入口（清理未结束的批次须显式要求先停止）；与 GUI 共用决策、覆盖及发布判定。长参数列表不作为大批量输入的唯一方式。
- 非交互运行必须显式指定可自动处置的策略与发布授权；缺少必要配置立即返回可解释状态，不猜测默认授权。遇到需要输入密码或人工决定的文件时记录为阻塞并继续独立成员，不能无限等待 stdin。交互式终端可无回显输入密码（FR-09），不接受以参数或环境变量传入。
- 建议退出码：`0` 表示请求范围内全部文件已按策略发布，`2` 表示至少一项待复核 / 阻塞 / 失败 / 部分结果或未交付，`1` 表示调用错误或批次无法启动，`3` 表示用户中断。机器可读报告保留逐文件原因，不能从非零退出码推断已成功成员需要重跑。
- 每次调用明确操作范围；恢复、重试绑定原批次和配置快照，发布幂等。MVP 中批次由创建它的入口（GUI 或 CLI）继续管理；同一工作区同一时刻只有一个修改者，冲突按架构文档 6.1 节返回明确状态；CLI 默认使用独立于 GUI 的工作区，可显式指定，因此托盘常驻的 GUI 不阻塞 CLI 的默认调用。无法取得平台密钥（如无图形会话）时返回 `1` 及明确原因，不弹窗等待。GUI 与 CLI 之间交接批次及复核决定（一方保存的决定由另一方继续使用）列为 P1。
- 支持结构化进度输出；stdout、stderr 及策略包遵守 INV-07，策略包不携带敏感词表原值或凭证。

### 3.7 插件管理（P0）

MVP 除内建插件外，支持用户安装第三方插件以扩展格式、检测、OCR 或验证能力，以及只含规则数据的规则包（FR-46）。第三方代码插件能读到文档明文，以下产品规则与 SEC-07、SEC-14 共同构成开放前提；实现约束见架构文档 4.3 节。

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-40 | P0 | 支持从 git 仓库或本地路径安装第三方插件，并可启用、停用、卸载、升级及回退；用户无需自行安装 git、Python、uv 或 pip。git 来源按提交固定版本，不跟踪分支或标签的后续变化；本地路径在安装时形成不可变快照，之后对源目录的修改不影响已安装版本 |
| FR-41 | P0 | 安装前一次性展示来源、提交或摘要、插件清单、角色与格式、请求的权限及资源声明、插件声明的许可证及依赖摘要，用户确认后才部署。需要联网下载依赖时单独提示，并与文档处理完全分离；支持以本地路径加预编译依赖离线安装。插件及其依赖的许可合规由插件作者负责，Tacet 只展示声明，不代为判断 |
| FR-42 | P0 | 停用后插件不再用于新任务；引用该版本的运行中或可恢复任务继续使用原版本，或由用户明确作废。卸载时，仍被运行中、待复核、可恢复任务或未到期保留数据引用的版本不删除，展示引用项供用户选择等待或作废；卸载不影响已发布输出，记录可追溯。升级视为安装新版本，重新确认来源、权限与许可，旧版本可回退 |
| FR-43 | P0 | 第三方插件不能静默接管内建格式；多个插件声明同一格式时由用户选择默认实现，任务快照记录所选插件及版本 |
| FR-44 | P0 | 报告和交付清单标注抽取、回写及验证由哪个插件完成。第三方格式插件的结果默认不获得“已按策略完成”和无人值守发布资格；用户对该插件版本单独授权后方可获得，升级后授权不自动继承 |
| FR-45 | P0 | 第三方插件按 SEC-07 在 OS 沙箱内运行；某平台沙箱未通过验收时，该平台不提供第三方插件的安装与启用，不降级为无沙箱运行 |
| FR-46 | P0 | 支持规则包：只含声明式规则数据（词表、正则、字段路径及已注册校验器的引用）的插件包，不含可执行代码，由内核规则引擎执行。规则包沿用 FR-40 至 FR-42 的来源、固定版本、确认、启停、卸载与回退规则；安装时校验语法与规则预算，不合规时拒绝而非截断；其规则集只读，复制后可编辑。规则包不受 FR-45 的沙箱前提限制。只由第三方规则包提供检测来源的类别不获得无人值守资格（6.2 节）。实现见架构文档 4.7 节 |

## 4. 文件格式与能力分级

### 4.1 建议的交付顺序

| 格式 | 阶段 | 必备输出能力 | 主要要求 / 边界 |
| --- | --- | --- | --- |
| TXT、Markdown、日志 | P0 | 相同文本格式 | 增量解码；保持明确的编码与换行策略；不得整文件拼接；数百 MiB 级日志建议使用仅规则 / 整字段模式（FR-18、PF-01） |
| CSV | P0 | 结构正确的 CSV | 正确处理引号、分隔符、跨行字段、表头上下文及公式注入风险 |
| JSONL | P0（次要场景） | 可逐行解析的 JSONL | 按记录处理；超大单记录也需受限，字符串值转义正确 |
| JSON | P0（次要场景） | 有效 JSON | 流式解析大数组及长字符串；键名、值和类型变化有明确策略 |
| 文字型 PDF | P0（核心） | 栅格化安全 PDF | 以 pdfium 提取文本及字符坐标用于检测与预览，并核对文本层与可见内容的一致性；输出按页渲染、在像素上删除并重建新文件，禁止仅盖黑框；导出前告知失去可搜索文本、链接、表单与矢量版式。要求见 4.3 节，验证见 6.3 节 |
| DOCX | P0（核心），限定能力 | 脱敏 DOCX | 正文、表格、页眉页脚、基础属性；修订、批注等须按能力移除或处理 |
| 扫描 / 混合 PDF、PNG、JPEG | P1 | 处理后的 PDF / 图片 | 本地 OCR、坐标映射、像素删除；混合页不能仅凭存在文本层就跳过图像 |
| 保留结构的 PDF 删除 | M2 | 保留文本层的脱敏 PDF | 删除真实文本 / 图像内容，完整重写并清理已失效对象；引擎按第 8 节的许可决策选择（商业授权或单独发布的插件） |
| DOCX 输出为 PDF | P1 | 脱敏 PDF | 需评估本地渲染引擎的保真、体积、许可与攻击面；渲染在受限工作进程中执行 |
| XLSX 值子集 | P0 候选（须通过 M0 准入，否则 P1） | 脱敏 XLSX 或明确选择的表格副本 | 单元格值按字段策略与检测处理；共享字符串、隐藏表、批注、公式及缓存、透视缓存、外部连接按部件清单处理，无法安全处理的部件整体移除或阻塞 |
| XLSX 完整能力 | P1 | 脱敏 XLSX | 流式处理；公式与缓存的保真处理及复杂工作簿结构 |
| PPTX | P1 | 脱敏 PPTX 或明确选择的 PDF | 正文、备注、图表、图片及嵌入对象覆盖声明 |
| EML、MSG、RTF、ODT / ODS / ODP | P2 | 由插件声明 | 附件递归、编码和格式专属部件 |
| DOC、XLS、PPT | P2 | 转换后的现代格式 | 本地隔离转换；转换失真、宏和签名变化须告知 |
| ZIP 等通用归档 | P2 | 受限递归处理 | 路径穿越、递归深度、解压体积与嵌套文件均受限；OOXML 内部 ZIP 不受此阶段限制 |

表中阶段为范围建议，P0 为 M1 的候选范围，逐格式按第 10 节的准入规则冻结；百兆级要求只适用于对外声明支持大文件的插件（PF-01）。

### 4.2 覆盖范围与部件处置

对每个文档部件分别记录三个相互独立的维度，不用单个状态同时表达“是否检查”和“是否保留”：

| 维度 | 建议取值 | 含义 |
| --- | --- | --- |
| 检查状态 | `inspected`、`not_inspected`、`unsupported`、`failed` | 是否完成本次策略要求的内容检查，未检查原因需可追溯 |
| 输出处置 | `redacted`、`removed`、`retained_by_policy`、`pending` | 已脱敏、整体移除、明确保留或尚未决定；保留不推导出已检查 |
| 验证状态 | `passed_within_declared_scope`、`partial`、`failed`、`not_run` | 对该部件处置的执行效果和残留检查结果 |

**必查范围。** 覆盖清单列出本次策略必查的部件、内容类型及类别范围，不因格式插件不支持而自动移出必查范围。一个部件的文本已检查，不代表其中的图片、附件或未启用类别已检查；事先未纳入策略的类型列为范围外，不能借 `passed_within_declared_scope` 宣称已检查所有类型。

**完整登记。** 格式插件须登记输入中实际存在的全部部件（含未引用、未显示及解析器不认识的内容），并逐项记录输出去向；仅列出解析器认识的部件不算完整。枚举须有完成标记，未完成按 INV-02 处理；结构歧义、重复条目名或无法可靠枚举时明确失败或形成缺口，不按解析器默认行为静默取舍。技术要求见架构文档 4.1 节。

**覆盖缺口与处置。** 必查部件未检查、不支持或检查失败却仍被保留，或存在未知 / 不透明内容时，即构成覆盖缺口；未知内容不因缺少正常引用或未显示在页面上而豁免，也不能自动归为纯结构。用户同意保留不消除缺口。存在缺口的文件只有三种去向：

1. 经授权整体移除该部件并验证不再残留：消除输出暴露，但报告保持其原检查状态，只能声称“已移除”，不能声称已识别其内部实体；
2. 阻塞该文件；
3. 按 FR-35 发布部分结果：前提是未检查范围可明确界定，且文件边界、结构有效性及已批准操作效果均已验证，否则必须阻塞。

复核界面把第 1 种去向显示为“涂抹”，把第 3 种显示为“保留”并标注将形成部分结果；不满足第 3 种前提时“保留”不可选，用户选择涂抹前文件保持阻塞（第 2 种）。

复核界面把第 1 种去向显示为“涂抹”，把第 3 种显示为“保留”并标注将形成部分结果；不满足第 3 种前提时“保留”不可选，用户选择涂抹前文件保持阻塞（第 2 种）。

已知纯结构部件可按明确规则保留并验证；已检查并按策略保留的内容记录保留依据与适用位置。

**首版办公文档的默认处置。**

- 文字型 PDF / DOCX 中的图片、截图、扫描页或嵌入文件，在 OCR 交付前默认计入缺口；不能仅因页面有文本层就声称整页通过。中文办公材料常含身份证复印件、公章、签名及简历照片，首版为此提供以下 P0 动作，可在批次开始时按类型一次授权（BUX-01），也可在例外复核中按分组决定：
  - **涂除页内图像**（PDF）：在栅格输出中把图像在页面上的可见区域（按变换后的外接矩形外扩）填为纯色，并标注“图像已移除”；
  - **移除图片**（DOCX）：删除原媒体部件，原位置换为同尺寸的中性占位图以保持版式，并清理相关关系、替代文字及缩略图；
  - **移除嵌入文件 / 对象**（PDF / DOCX）：删除部件及其引用，原位置保留类型占位说明。
- 内建“通用办公外发”策略默认对上述图像及嵌入内容执行整体涂除 / 移除，按上文第 1 种去向报告为“已移除”，不声称已识别其中的实体；批次开始前展示受影响的文件数与图像数，用户可改为保留并按 FR-35 发布部分结果。图像覆盖页面大部分且无可用文本层的扫描页，默认阻塞该文件并说明需要 OCR（P1），或经授权整页涂除。
- 栅格化 PDF 输出对全部输入部件统一处置为“不复制”，仅由处理后的页面图像及最小文档结构生成新文件，验证要求见 6.3 节。页面位图内的文字会被原样带入输出，在 OCR 交付前仍计入覆盖缺口。

### 4.3 格式专属要求

- DOCX：处理跨多个 run 的实体；不得用整个段落字符串覆盖来破坏格式。脚注、尾注、超链接、文本框、批注、修订、图片、嵌入文件、文档属性、`customXml`、缩略图及未知扩展部件逐项登记并声明策略；未引用的 ZIP 条目也须计入。不能只删除批注引用而保留实际批注 XML。复核、报告与清单中的定位使用页码加章节段落：页码依据文档保存的分页标记推算，可能与实际打开时的分页不同，标为约数，没有分页标记时不显示；章节取最近的标题，没有标题时以段落序号定位。实现见架构文档 4.5 节。
- XLSX：需要遍历隐藏 / veryHidden 表及隐藏行列；处理共享字符串中的原值、公式及缓存、批注、超链接、名称和外部连接。不得为了显示脱敏而保留敏感原值。公式不能被静默破坏，也不能通过自动计算重新生成已移除的敏感信息。
- PDF：建立文字到字符坐标的映射，处理旋转、双栏、跨行、重复文字、OCR 层及图像。MVP 栅格化输出按页渲染，删除区域按字符框外扩并覆盖抗锯齿边缘，只用处理后的页面图像及最小结构重建新文件，不复制原文档的任何对象（含文本层、字体、附件、元数据、表单、可选内容及增量历史）；声明渲染分辨率（默认 200 DPI，可选 150 / 300）、色彩、压缩方式及预计体积。随页面渲染进输出的注释、表单字段等可见内容同样须进入检测与复核：首版先在内存中展平注释与表单，再对同一展平结果抽取文本和渲染；展平失败的页面将注释记为覆盖缺口。栅格化输出会带出全部可见内容，因此文本层与可见内容不一致的区域不得声称已检查：字符缺少有效 Unicode 映射（如缺 ToUnicode 表或 Type3 字体无映射）、可见图像中的文字，以及经确认的文字转曲区域，均按页面区域计入覆盖缺口并进入例外；疑似文字转曲的密集路径区域由用户在复核中确认是否含文字，确认结果按 INV-01 记为人工决定。中文 PDF 常见未嵌入字体，渲染时的字体回退须在 M0 验证保真，报告列出使用回退字体的页面。实现见架构文档 4.5 节。M2 保留结构的删除须另行制定附件、表单、批注、书签、元数据、可选内容及增量历史的清理策略，最终输出不得保留含原文的增量历史。
- 扫描件：OCR 提供的行框不等于字符框；精确遮盖需字符对齐，无法可靠对齐时提供保守区域处理及复核。极大图片需分区域处理和像素数上限。
- 结构化文本：检测范围与输出类型约束分别定义。字符串值默认检测；数字原始词法值结合字段名、表头、规则及相邻上下文检查，不能仅因其非字符串就跳过手机号、证件号、账号等。键名也检测，命中后按事先授权处理；未经授权不改键，作为例外呈现。路径和日期按启用类别处理，禁用类别在策略摘要中明确。
- JSON / JSONL：数值采用精确数值或原始词法表示，未命中值不得经普通浮点往返而改变大整数、精度或科学计数内容；重复键不能静默合并。敏感数值改为占位符字符串、`null` 或其他替代值，必须有明确授权及类型 / schema 约束；无可用替代时阻塞对应文件，不能把原值保留为“脱敏成功”。改键需检查冲突、重复键和引用影响，无法满足约束时进入复核。
- 所有格式：宏、外部资源及嵌入程序遵守 INV-08，默认移除或明确报告；签名文件修改后应说明签名失效，不得保留“签名仍有效”的错误表现。

## 5. 性能与资源要求

### 5.1 指标状态与参考环境

本节数值是建议的工程目标，尚未实测。原型验证后，应以实际硬件、固定语料、模型版本和后端冻结发布门槛；调整需记录依据，不能把目标写成已实现性能。

容量单位使用 MiB / GiB（1 MiB = 1,048,576 字节）。文件体积、解压体积、提取字符数、token 数、页面像素和命中数分别统计。

| 环境 | 建议配置 | 用途 |
| --- | --- | --- |
| R1 基础设备 | 8 GiB RAM、4 个物理 CPU 核或等效能力、SSD、至少 15 GiB 可用磁盘；无独立 GPU。macOS 与 Windows 各选一台代表机型，如 8 GiB 统一内存的 Apple M1 机型及 4 核 x64 笔记本 | CPU 轻量模型、大文件稳定性和交互验收 |
| R2 常见设备 | 16 GiB RAM、8 个物理 CPU 核或等效能力、SSD、至少 25 GiB 可用磁盘；macOS 与 Windows 各选一台代表机型 | 标准档吞吐与并发验收；后续 OCR 及 M2 可选模型资源包也在此档验收 |
| R3 加速设备 | 具体 GPU / Apple Silicon / NPU 型号及驱动单列 | 默认开启 GPU 加速，环境支持时优先 GPU；关闭或不可用时同模型版本降级 CPU，仍须验收 CPU 路径 |

验收报告必须补齐具体 CPU、OS、RAM、磁盘、模型摘要、推理后端、线程数、功耗模式和后台负载，不能只写“普通电脑”。共享内存 GPU 也计入整机内存压力评估。

### 5.2 建议的可量化目标

| 编号 | 指标 | 建议目标 / 测量方式 |
| --- | --- | --- |
| PF-01 | 大文件容量 | 对每个声明支持大文件的插件，通过 100 MiB 有效样本的全流程测试，并按格式声明页数、内嵌图片数及文本量上限；流式文本与结构化格式另须通过 500 MiB 样本的内存有界测试（PF-08），该样本使用仅规则 / 整字段模式（FR-18），不要求模型全开时在可接受时间内完成 |
| PF-02 | UI 响应 | 处理中点击、滚动及切换面板反馈 P95 ≤ 200 ms；自有 UI 主线程无持续超过 1 s 的同步阻塞 |
| PF-03 | 任务反馈 | 接受任务后 1 s 内显示排队 / 预检状态；长阶段每 1 s 更新状态或心跳，不要求 1 s 内完成探测 |
| PF-04 | 取消 | 点击后 200 ms 内确认请求，5 s 内停止该任务的重计算和持续写入；清理可异步并显示状态 |
| PF-05 | 暂停 | 5 s 内停止派发并到达安全边界：声明大文件能力的插件到达阶段内检查点，其他插件放弃当前未完成的阶段、恢复时重做（FR-05）；不可中断步骤显示等待原因并允许转为取消 |
| PF-06 | 基础档内存 | R1 上采用轻量 CPU 模型时，应用进程树总内存预算 2 GiB，统计 UI、工作进程、模型、映射与缓存；macOS 无进程树硬限制，按架构文档第 10 节以监控与回收方式验收 |
| PF-07 | 标准档内存 | R2 默认总预算 4 GiB；更大模型或加速档须预检并重新分配，不能隐式突破预算；M2 的可选模型资源包仅在通过其内存预检的设备上可选 |
| PF-08 | 内存增长 | 预热后，同构 100 / 500 MiB 样本（500 MiB 按 PF-01 使用仅规则 / 整字段模式；办公文档以页数成比例的同构样本代替）的峰值差目标 ≤ 256 MiB；允许磁盘状态增长，不允许结果表全驻内存 |
| PF-09 | CPU 礼让 | 舒适档建议总平均 CPU 不超过整机等效算力约 50%；10 s 窗口测量，可按平台降并发 / 休让 |
| PF-10 | 队列与缓存 | 待处理队列默认总上限 64 MiB，并限制单元数；预览缓存单独受预算管理 |
| PF-11 | 临时磁盘 | R1 默认任务临时区上限 4 GiB，R2 为 8 GiB；候选输出另设预检空间与配额，不算作无限可用空间 |
| PF-12 | 异常隔离 | 单个插件崩溃、超时、超预算时，控制器仍可响应、报告并取消 / 重试其他任务 |
| PF-13 | 长时间稳定性 | R1 / R2 各执行至少 4 h 连续任务；同构任务完成后的稳定内存不持续增长，建议增长 ≤ 10% |
| PF-14 | 大结果集 | 单批次 10 万条候选命中可落盘、分页查询、分组批量决定和复核；不因全量成员 ID、前端列表、撤销记录或导出计划耗尽内存；用户可完成性另须通过 5.5 节 |
| PF-15 | 冷启动 | R1 已安装资源时，5 s 内出现可交互主界面；模型加载异步显示，不以模型就绪作为开窗前提 |
| PF-16 | 批量复核查询 | R1、10 万候选索引就绪后，常用筛选 / 分组首屏加载目标 ≤ 2 s；后台批量提交 200 ms 内反馈，长操作可查看进度，提交完成时间单列 |
| PF-17 | 多文件与累计存储 | 逐文件任务及批次结果可分页，不为每文件常驻解析器 / 模型；预检并限制全部待复核、待发布、检查点及候选文件累计空间 |

内存预算是资源控制要求，非仅在任务结束时检查。平台支持时使用硬限制；否则设置较低软阈值并由外部监控回收工作进程，保留 UI / 控制器余量。报告采样峰值、平台内存口径、共享页去重方法及观察到的越界，不把简单相加 RSS 当作精确物理占用。

系统可用内存低于安全阈值时应先暂停新单元、释放缓存、降低模型 batch / 并发；无法恢复则停止重计算，在所选保留期限内保存检查点。不能依赖系统交换空间维持表面上的运行，也不能让“用户已提高预算”绕过整机可用资源检查；磁盘的批次累计预算见 PF-17。MVP 不在多个应用实例之间分配计算预算：同一 OS 用户同时运行多个 GUI / CLI 实例时，各实例分别按资源档执行，由上述整机可用资源检查兜底，用户帮助说明同时运行多个重任务的影响；跨实例计算准入列为 P1。

### 5.3 吞吐与耗时验收

总耗时高度依赖文本密度、模型、OCR、文档结构和输出模式。首轮不预先承诺统一的“100 MiB 几分钟”，但发布前必须为每个支持配置给出可复现的耗时数据。

- 分别记录解析 MiB/s、检测原始有效 token/s、OCR 页 / 分钟、导出页 / 秒、验证耗时和端到端机器运行耗时；重叠 token 额外统计，人工复核等待时间单列。
- 同一配置至少执行 5 次，记录冷 / 热启动、单次结果、中位数与最大值；不足以可靠估计 P95 的样本数不得标注 P95。
- R1 CPU 档必须完成一份 100 MiB 级、数百页的中文 / 混排 DOCX 或文字型 PDF 的全流程（含栅格化输出与验证），不能只展示模型单窗口速度。
- 对声明 500 MiB 能力的流式格式，在仅规则 / 整字段模式下，同构 100 → 500 MiB 输入的端到端机器运行时间建议不超过 6.5 倍，办公文档按页数做同样的规模线性检查；索引、输出和验证均计入，非线性例外需解释并缩小支持范围。
- 模型全开时的可处理文本量受 R1 CPU 推理吞吐限制，按粗估数百 MiB 文本可能需要十余小时，以 M0 实测为准；吞吐表须给出模型全开的建议文本量上限，超过时在预检中提示改用仅规则 / 整字段模式，不以免责声明代替。
- 建立每个“格式 × 模型 × 硬件 × 资源档”的最大可接受耗时；该表是首版发布前必填项，不能以“不崩溃”替代可用速度。
- 同配置版本回归建议：吞吐下降超过 15% 或峰值内存上升超过 10% 时需分析；更高召回或更完整验证造成的成本变化应明确说明。

### 5.4 复杂度上限与超限行为

以下为原型阶段的初始保护建议，发布值由格式插件及资源档冻结：

| 对象 | 建议初始上限 | 超限行为 |
| --- | --- | --- |
| 解压 / 解码累计体积 | 单任务 8 GiB，并设置解压比和递归深度限制 | 停止相应输入并报告超限位置（INV-02） |
| 单文本处理单元 | 建议 ≤ 1 MiB 原始文本，再按模型 token 上限切分 | 保留位置与上下文进行二次切分（INV-02） |
| 单张解码位图 | 建议 ≤ 32 百万像素，按实际像素格式计费 | 降采样仅作预览；检测需分区域处理或明确拒绝 |
| PDF 页数 | 建议初始 ≤ 2,000 页 | 预检时拒绝，标为“无法处理”并提示实际页数与上限（INV-02）；按页范围拆分为多个成员列为 P1 |
| DOCX 结构与媒体 | 按解压体积、XML 节点数及内嵌媒体数分别设限 | 超限停止并报告超限部件（INV-02） |
| 栅格化输出 | 默认 200 DPI，按页像素及输出总体积预检 | 预计体积超出配额时提前提示降低分辨率或释放空间（拆分为 P1，见上）；不得为压缩体积降到无法辨认的分辨率后仍宣称可用 |
| 单文件 / 批次并发 | 舒适档默认 1 个重任务，OCR / 推理复用受限实例 | 其他任务排队，禁止每文件无限创建线程池 |
| 插件执行时间 | 按探测、页面、窗口、导出阶段分别设截止时间 | 心跳不能无限续命；阶段超时可取消 / 重试，输出不完整状态 |

队列上限见 PF-10，单条协议消息上限见架构文档 4.2 节。

对 1 GiB 文本、压缩炸弹、超大单记录、超大页面等压力样本，允许超出声明能力后明确拒绝；必须保持控制器可响应。普通有效文件与恶意样本的验收标准分开。

### 5.5 用户完成任务的可行性

以下是首轮交互原型的目标，须在 M0 以固定任务和目标用户验证后冻结。有效人工时间计入策略选择、阅读、复核、纠错及发布操作，机器等待时间单列；同时报告端到端总历时、人工操作数、逐项与批量决定数、任务完成率和错误结果。不能只统计点击速度，或靠降低检测范围达到目标。

| 场景 | 固定测试条件 | 建议目标与通过条件 |
| --- | --- | --- |
| UX-00 单份文档快速外发 | 一份 5 至 20 页的 DOCX 或文字型 PDF 合同 / 简历，约 50 条候选，含 1 张证件照或公章图片；使用内建“通用办公外发”策略，无预置例外 | 从导入至拿到输出的有效人工时间 ≤ 2 分钟，主要提交操作 ≤ 3 次；R1 上的机器耗时目标 ≤ 60 s，M0 实测后冻结；没有批次专用的强制设置步骤，图像默认处置在提交前可见 |
| UX-01 同类文档批次 | 200 份同类办公文档（如简历或同一模板合同，DOCX 与文字型 PDF 混合），累计约 2 万条候选；标准策略适用，无注入例外 | 从导入至进入结果页的有效人工时间 ≤ 15 分钟、主要提交操作 ≤ 10 次；无逐文件弹窗、无逐页确认；结果页准确显示交付范围，交付清单能按需核对全部成员 |
| UX-02 有集中例外的批次 | 200 份混合办公文档、约 2 万条候选，预置 20 个可按相同依据解决的例外组，每组预置 3 个代表样例及明确处置依据 | 有效人工时间 ≤ 30 分钟；20 组均完成正确处置，不能依靠默认保留或隐藏问题缩短时间；打开明细不要求逐文件导航 |
| UX-03 大型单文档 | 一份 100 MiB 级、数百页且含大量图片的 PDF 或 DOCX，数千条候选，其中多数可按类别统一处置 | 按类别、页范围或例外原因一次决定，不随页数增加逐页确认；分页预览能定位任一候选及未检查图片；导出前明确栅格化或保真损失 |
| UX-04 中断与局部重试 | 批次复核后重启应用；另模拟 10 个文件失败，其余已交付 | 启用恢复时继续原复核位置且已提交决定不丢失；用户可用一次有范围摘要的动作重试失败成员，已交付文件不重新生成 |
| UX-05 无人值守与阻塞 | 固定策略下运行 200 份办公文档，混入需密码、含嵌入文件或截图等未检查部件和输出暂不可写的成员 | 无需运行时输入即可结束此次调用，合格成员按授权交付，其余逐文件明确列出；非完整成功退出状态、GUI 和报告一致 |
| UX-06 结构化数据（次要场景） | 100 份结构相同的 CSV / JSONL，累计约 10 万条候选，字段策略可统一处理 | 每个字段规则一次应用于全部授权记录，不随记录数增加逐项确认；预览能发现类型与结构异常 |

“主要提交操作”指会改变策略、复核决定或发布状态的提交；导航、阅读和滚动另行统计，不能通过把多个强制确认藏进向导来规避。UX-02 的分组与代表样例只验证该固定任务下的操作可行性，不推导真实数据均可归为 20 组，也不证明未抽查成员无隐私风险。

- M0 至少邀请 5 名办公外发场景的目标用户使用固定说明完成关键流程；报告每人的完成情况、有效人工时间及误操作，不以少量样本标注 P95。初始目标为至少 4 / 5 在限定时间内正确完成 UX-00、UX-01、UX-02 的流程，测试中不得发布被预置规则要求阻塞的文件；未达到时调整流程并重测。
- 同一轮测试验证目标用户对栅格化 PDF（不可搜索、体积变化）及 DOCX 预览形态的接受度；不接受时调整 M1 / M2 范围，不能靠免责声明通过。
- 必须另外测试结构异构、例外无法合并和低质量文件占比高的场景。此时不承诺固定 30 分钟完成全部复核，但应展示剩余独立决定数、可用处置和工作量依据，允许按子集交付、暂停保留、整体移除经授权的部件或停止；不能迫使用户只靠逐条确认继续。
- 若用户操作中形成的大量保留例外或误报使复核成本失控，应改进字段规则、上下文分组或收窄适用场景；不能将“用户最终负责”作为可用性验收通过理由。

## 6. 检测质量与输出质量

### 6.1 自有评测集

评测集使用合成数据、经授权并去标识化的数据，建立开发 / 校准 / 独立测试划分。同源文档、近重复内容和同一模板生成的变体按组划分，避免批量重复样本同时进入校准与测试造成虚高。建议首轮至少 1,000 个独立文档或记录组、10,000 个标注敏感实体；核心类别尽量各含至少 500 个实例，不能达到时单独报告，不以微平均掩盖。500 个实例并不自动足以证明 99.5% 的发布门槛，所需样本与置信区间规则须在 M0 冻结。

覆盖中文、英文、混排、繁简体、罕见姓名、缺分隔符号码、OCR 错字、格式噪声、跨 run / 跨行 / 跨块、表头上下文、长文档和无敏感内容的负样本。包括数字形式手机号 / 证件号、超过浮点精确范围的大整数、敏感键名、同值在不同上下文中的保留例外、批量字段策略及验证新命中。文档类别至少含合同、简历、清单、财务材料、日志与配置。

### 6.2 质量指标与建议门槛

| 指标 | 定义 | 建议验收方式 |
| --- | --- | --- |
| 精确片段 P / R / F1 | 类型与起止位置完全匹配 | 按类别、语言、文档类型及模型配置分别报告 |
| 完整覆盖召回率 | 完整删除策略下，标注实体的全部敏感字符均在自动建议的删除 / 替换范围内 | 防止只遮住号码的一部分也算正确；按下方 P0 类别清单分别验收 |
| 精确率 | 自动提出的实体中正确比例 | 各类别目标见下表；不同策略允许公开的取舍 |
| 文档遗漏率 | 含至少一个未完整处理标注实体的文档占比 | 按格式、语言、长度及实体密度单列；M0 冻结各声明场景的上限，未达标不进入对应无人值守范围 |
| 误报文档率 | 无敏感信息文档中出现候选的比例 | 单独报告，衡量复核负担 |
| 回写正确性 | 已批准操作是否在正确源位置完整执行 | 确定性回写测试集须 100% 正确 |
| 残留与保真 | 目标原值、未处理部件及非敏感内容变化 | 专项验证集无已知可恢复残留，无未经声明的结构破坏 |

上述检测比例是待原型验证的目标，不是模型作者分数的复述。自动检测指标在人工复核前测量；人工复核后的效果另外报告。部分掩码等有意保留信息的策略按预定目标字符范围评价，不与完整删除策略混算。评测需报告样本量、置信区间、标注政策和实际达到值；样本不足以支持的细分结论标记为证据不足。视觉隐私等未覆盖类别不得纳入通过结论。

首轮 P0 类别的检测组合及独立目标如下（R 为完整覆盖召回率，P 为实体精确率，均为人工复核前测量、待 M0 验证的目标）。每个类别与子类单独验收，不以平均值、合并类别或部分字符覆盖代替；数值按实际发布配置的模型与规则组合评测。

| P0 类别 / 子集 | 必须具备的检测来源或策略 | 初始目标与发布限制 |
| --- | --- | --- |
| 手机、座机、邮箱 | 声明地区的格式规则、上下文模型，号码规范化保留映射 | 各类别 R ≥ 99.5%、P ≥ 99%；地区与异常格式单列 |
| 中国居民身份证号 | 格式、校验、字段上下文及疑似值规则 | 标准与疑似样本分别报告，标准子集 R ≥ 99.5%、P ≥ 99%；数字存储与末位 X 均覆盖 |
| 银行卡 | 格式 / 校验、财务上下文及模型 | 声明卡号范围 R ≥ 99.5%、P ≥ 99%；会员卡、工号不计入 |
| 人名、私人地址 | 上下文模型、适用词表及人工补充入口 | 两类各 R ≥ 97%、P ≥ 95%，中文、英文、混排分别报告 |
| 个人账号、员工号、会员号 | 字段规则、上下文模型及整字段处理 | 各声明子类 R ≥ 97%、P ≥ 95%；未知内部编号不能被笼统承诺覆盖 |
| 生日、证件日期、就诊日期 | 模型加字段 / 日期规则；需要时显式选择全部日期处理 | 三个子类分别 R ≥ 97%、P ≥ 95% |
| 已知格式 API Key、Token、Cookie、私钥 | 格式 / 字段规则、跨行处理及模型 | 各声明凭证族 R ≥ 99.5%、P ≥ 99%；单独测试完整值覆盖 |
| 无固定格式密码与凭证 | 有上下文的模型 / 字段规则，或授权整字段处理 | 有上下文子集 R ≥ 97%、P ≥ 95%；无上下文任意随机串单列局限，不自动获得无人值守资格 |
| IP、URL | 格式规则、字段策略及局部凭证检测 | 整体处理子集 R ≥ 99.5%、P ≥ 99%；选择局部处理时按对应敏感子类另行验收 |
| 企业词条、项目代号 | 固定词表与已定义的大小写 / 边界 / 规范化规则 | 确定性匹配与位置测试 100% 正确；不推导能识别未配置的语义别名 |

每一项还须冻结适用语言、格式子结构、测试样本、置信区间要求及文档遗漏率上限。证据不足或未达标时应补充规则 / 专项模型、要求适用范围内的人工复核或整字段保守处理，或明确缩小发布范围；仅提高置信度阈值、增加免责声明或让用户确认一张样例，不能使该配置获得无人值守资格。人工复核若被列为必要控制，也必须通过 5.5 节的可完成性验证。

对“99.5% 实体召回”等结果，不得推导大文件有同等概率完全无遗漏；按实体密度分层报告文档遗漏率及长文档表现。发布前的无人值守资格依据独立评测及冻结范围确定，不由某一批次“没有候选”或抽查通过临时授予。

### 6.3 输出正确性

- 纯文本：无格式规定的变化之外，未命中范围的字符保持一致；编码转换有明确说明。
- CSV / JSON / JSONL：可重新解析；字段、记录和类型变化仅限策略允许范围；未命中数字保持精确值及约定词法形式，未声明改键不得变更键名，重复键不能被静默丢弃。整字段处理、空值与异常类型分别验证。
- DOCX / XLSX / PPTX：可由 Microsoft Office 与 WPS Office 的约定版本（M0 冻结）正常打开，不出现修复提示；章节、单元格、页眉等结构保留范围可验证，全部容器条目的处置及实际输出部件可核对，特殊部件变化可追溯。
- 栅格化 PDF（MVP 默认）：重新枚举输出，只含处理后的页面图像及白名单内的最小结构；文本提取结果为空，不含旧对象、文本对象、字体、附件、元数据、表单、可选内容或增量历史；每个已批准操作对应的像素区域完整覆盖；抽检非敏感区域在声明分辨率下可辨认；文本层与可见内容不一致的区域已计入覆盖缺口，报告列出使用回退字体的页面。
- 保留结构 PDF（M2）：重新提取和渲染均符合预期；已删除文本无法通过文本提取、旧对象或保留的图像副本恢复；抽检非敏感区域视觉差异。
- 栅格化 PDF 加 OCR 文本层（P1）：OCR 层只能从已处理输出生成，并再次验证。

### 7.1 数据生命周期与恢复授权

跨工作进程的故障恢复检查点与跨应用重启的保留是两种能力。当前运行中的检查点默认启用并受加密及配额约束；跨应用恢复在批次开始时统一选择，避免处理中反复询问。建议启用时默认保留 7 天，可缩短或明确延长；期限从最近一次用户明确保存 / 恢复操作计算，后台心跳不自动续期。

| 状态 / 操作 | 默认行为 | 用户可选与清理要求 |
| --- | --- | --- |
| 运行中 / 工作进程异常 | 在当前会话保存必要检查点、复核决定和受保护候选，允许局部重试 | 受任务与批次配额约束；不因此获得无限期跨应用保留授权 |
| 暂停 / 等待复核 | 当前会话保留，显示待处理数量、空间及保存状态 | 启用跨应用恢复时显示到期时间；关闭应用前统一处理未保存授权，不能按文件逐个询问 |
| 关闭窗口（默认最小化到托盘） | 窗口隐藏，任务继续运行，托盘显示进度与待处理数量 | 可在设置中改为“关闭程序”；从托盘退出或改为关闭程序后按下一行处理 |
| 关闭应用 / 主应用崩溃 | 未启用跨应用恢复的敏感工作区不可作为长期恢复数据 | 正常关闭时集中提供“保存以便恢复”或“停止并清理”；有复核选择写入失败时，“停止并清理”只清理这些选择所在的文件（单文件任务则清理该任务），其他未完成任务保留到下次继续，对话框列明范围；文件已开始导出而被拒绝的选择不算写入失败；崩溃后下次启动先清理未获授权残留，已启用者按期限恢复 |
| 取消 | 默认“停止并清理”，终止工作后删除中间数据及该任务恢复密钥 | 显式选择“停止并保留以便恢复”才保留必要检查点和复核决定，显示期限及占用；可读但未完成验证的候选不作为交付文件 |
| 完整 / 部分结果已发布 | 清理中间文本、原图、位置映射、撤销数据与私有候选 | 最终输出、已发布清单和去敏报告不自动删除；继续保留以便修改 / 再导出必须单独授权期限，本地源路径索引也受该期限约束 |
| 失败 / 目标暂不可写 | 不发布错误候选；当前会话可重试 | 已授权恢复时只保留必要数据和仍有效的已验证输出；验证失败候选默认清理，不自动进入诊断包 |
| 到期 / 用户清理 | 清理敏感数据及不再被任何保留对象引用的任务密钥 | 到期时先阻止继续使用并清理；应用未运行时下次启动先执行。离线期间可能残留的密文不被声称已物理删除 |

- 密钥粒度必须允许清理单任务数据；共享词表、缓存及去重对象按授权引用计数管理，不能因其他任务仍在运行而无限保留已清理任务的可恢复原文。
- 清理界面展示完成、进行中或失败状态；被占用文件、权限错误及磁盘异常需可见且可重试。不能仅隐藏任务卡片就标记“已清理”。
- 首页“最近”列表的条目只含显示名（文件名或批次名）、文件数、状态、时间及导出位置，不含原文与命中，随工作区加密保存。任务数据清理后条目仍保留上述信息，使用户能看到该任务已停止或已导出；可逐条删除，清理工作区时一并清空，最多保留最近 100 条（架构文档 5.1 节）。
- 应用工作区默认使用私有、非同步位置（各平台位置见架构文档第 10 节），并按平台能力排除系统索引、缩略图与自动备份；说明 OS 崩溃转储、交换空间及管理员权限的保护边界。应用不承诺控制系统外部服务，但不主动把原文交给系统预览器或同步服务。

### 9.2 首版验收清单

发布前须同时满足以下条件，每项均需可追溯的测试证据：

- [ ] **性能**：第 5 节性能表同时记录目标与实测，吞吐与最大可接受耗时表已填写，无未说明的超预算；声明大文件能力的插件均按 PF-01 完成验证。
- [ ] **检测质量**：中文 / 英文 / 混排及全部 P0 类别 / 子类有独立结果、样本量与置信区间；文档遗漏率上限、默认策略及无人值守适用范围已冻结，未通过的范围已缩小或修正；按实际发布配置（策略、字段规则、例外分组及自动处置的组合）评测，不只验收裸模型。

- [ ] **插件与沙箱**：第三方插件的安装、启用、停用、卸载及平台沙箱在两个首发平台通过；沙箱未通过验收的平台未开放第三方插件，内建插件的降级隔离已按 SEC-07 标明。

- [ ] **用户接受度与帮助**：目标用户对栅格化 PDF 损失的接受度已验证；用户帮助覆盖策略模式、字段 / 分组操作、抽查局限、能力边界、输出差异、资源档位、取消恢复及交付 / 覆盖报告解释。

### 9.3 批量任务可用性验收方式

5.5 节的 UX 场景是发布验收，不以 PF-14 的容量测试替代。每个场景记录输入清单 / 合成方式、候选及例外分布、预期允许交付的成员、预设策略、硬件、资源档及用户说明；机器故障与人工判断错误分别记录。

测试至少包含导入、集中配置、查看自动处理摘要、定位例外、预览批量范围、纠正误报、补充遗漏、提交决定、暂停 / 恢复、局部重试、发布及清单核对。包含候选输出累计体积大于工作区预算的批次，验证一次明确授权后可在配额内逐文件交付，不依赖无限候选存储或反复清理弹窗。抽取未命中区域和预置高风险例外验证用户是否能发现并处理，不能仅使用“所有内容均可默认删除”的理想样本证明复核体验。

关键失败包括：误把未检查部件当作通过、批量范围扩大、逐文件强制确认、未经授权自动发布、已提交决定丢失、成功成员被重复重跑、部分交付被显示为全部完成，或验证失败候选进入共享目标。上述错误未解决时不能靠平均耗时达标通过。
