## 规模测量：200 份文本批次（macOS arm64，本机，一次运行）
`TACET_SCALE=1 go test -run TestBatchOf200Files ./internal/app`（`internal/app/scale_test.go`，内存密钥，不触碰钥匙串）：160 个 TXT（各 200 行，每行一个手机号与一个邮箱）加 40 个 CSV（各 300 行），仅规则预设，授权发布。
- 结果：200/200 `completed_per_policy`，退出码 0，交付 200 份，输出目录 600 个文件（交付件加报告）。
- 耗时 4 分 54 秒（约 1.5 秒/份）；`go test` 进程峰值 RSS 268 MiB，**不含** Python 插件进程；`2` 并发上限下插件进程的合计内存未测。
- 局限：这是单次测量，不是性能验收：未与需求中的耗时/内存目标逐项比对，未含 DOCX/PDF/XLSX 大文件、模型预设、R1 资源档与 Windows，也不是长期运行。每个阶段为每个文件新启动一个 Python worker，启动成本很可能是耗时的主要部分，未做剖析。
- 经命令行路径的同样测量未做：命令行默认使用系统钥匙串，本机该会话下报 `KEYSTORE_UNAVAILABLE`（按设计不弹窗、返回 1）。
