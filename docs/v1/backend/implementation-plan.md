# MVP 后端实施与验收计划

依据需求 v0.11、架构 v0.11、模块设计 v0.1。目标为完整 M0 + M1 P0 后端及现有前端的真实接线，P1/P2 不纳入。追踪表见 [requirements.md](requirements.md)，实现证据单独登记在 [evidence.json](evidence.json)。所有未验证项保持未完成。

## 起始状态

- 基线 HEAD：`fc2ffa69844396aa62e29ed8b849e199d7eaa6d7`。
- 开始实施时 `git status --short` 为空；目标拟定阶段观察到的前端未提交重构，此时已经以 `769b7b7`、`fc2ffa6` 进入 HEAD。以当前源码为基线，不回退这些提交。
- Go 40 个包中，大部分只有 doc.go 或类型、接口与常量；`app` 只有名称、版本及错误码，CLI 的六个业务命令返回 not implemented。`store.Tx`、`workspace.Session`、`sched.StageRunner` 等尚无执行实现。
- Python SDK 只有帧编解码；内建格式与模型包有清单和项目声明，插件模块尚无处理逻辑。协议只有 common、manifest、initialize、stream 四份 Schema，角色消息仍需补齐。
- `gui.Service` 仅提供 AppInfo 和关闭就绪；前端 TacetService 只有应用与窗口能力，业务处理使用模拟状态。真实接线必须通过 app/query，不能直接向前端暴露插件调用。
- 当前 Go 架构检查限制导入方向；它不能单独证明实体单写者、资源有界或实际安全行为，后续需行为测试与评审证据。

已查：Darwin arm64，Go 1.26.1，uv 0.13.1，Node 26.8.2，npm 11.19.1；Wails 位于 `~/go/bin/wails3`，当前 PATH 未包含该目录，验证入口临时添加。`/usr/bin/sandbox-exec` 与 Microsoft Word 已存在；安装存在不等于沙箱、授权或 Office 打开验证通过。

| 条件 | 当前状态 | 获得证据的方式 | 影响 |
| --- | --- | --- | --- |
| 本机 macOS arm64 | 可执行本地验证，硬件参考档未冻结 | 记录 OS/CPU/RAM/磁盘与功耗，实测后区分开发机和 R1/R2 | 本机结果不能冒充两个参考档 |
| Windows x64 | 尚无可用测试系统证据 | Windows 实机或适当虚拟机 + CI；验证 AppContainer、Job Object、DPAPI 和安装路径 | 必需验收保持未完成，跨编译不能代替 |
| Word/WPS | 本机有 Word，未发现 WPS | 固定版本打开 DOCX/XLSX 样本，记录无修复提示 | 缺少任一必要证据时格式准入不能完成 |

以上是条件清单，尚不意味着全部工作被阻塞；先推进可独立实现及本机验证的部分，触及受影响关口时报告具体证据和推荐操作。

## 执行顺序与关口

1. 建立需求、实现与验收清单，运行现有工程基线；零业务实现的需求不因骨架测试通过而标为完成。
2. 按架构 12.2 风险顺序验证 DOCX 跨 run/部件登记、PDFium 展平/栅格输出、AstrLink+规则质量、两平台沙箱、离线 Python 环境、加密存储与大列表。原型以真实插件和合成安全样本推进，记录实际结论；需要的最小基础设施随原型增量实现。
3. 形成明确的技术决策和格式准入记录，必要时请求产品范围决定。DOCX 与文字型 PDF 不得被 TXT 闭环替代；M0 未通过不得假称已进入全部 M1 验收。
4. 按模块设计顺序完善基础设施、运行时、任务控制、检测/覆盖、策略/复核、导出/验证/发布、管理与生命周期。
5. 完成 CLI 和 Wails 服务，再将现有页面业务动作接到真实服务；浏览器 mock 只用于开发与测试，生产处理不能由模拟计时器推进。
6. 运行各模块契约、跨模块、真实文件端到端与故障验证；执行规模、质量、两平台及长期验收。逐项核销需求追踪，留下可复现报告。

## 验证分层

| 层级 | 入口与覆盖 | 通过证据 |
| --- | --- | --- |
| 文档追踪 | `python3 tools/backend_trace.py --check` | 全部规范编号均映射模块和验收方法；设计变化需复核 |
| 纯逻辑 | Go 表驱动 | 状态迁移、失效、策略、例外动作、几何、覆盖与交付全部分支 |
| 插件契约 | Go/Python + Schema + 假插件故障注入 | 帧大小、协商、双维度额度、控制消息、取消与迟到结果 |
| 基础设施 | 临时工作区与独立进程 | 加密/WAL/备份、锁/代次、引用/密钥吊销、无覆盖发布与崩溃补记 |
| 真实格式 | 固定样本通过真实插件 | 编码与数字精度、DOCX 跨 run、PDF 像素与对象白名单、未知部件与残留 |
| 应用及入口 | app 用例、CLI、Wails 桌面 | 同输入判定一致、清单与退出码、真实事件及前端行为 |
| 规模与稳定性 | 100/500 MiB、200 文档、10 万候选、至少 4 h | 实际资源与时延曲线、后台交互等待、反复取消及句柄稳定性 |
| 发布所需外部验收 | 两平台、Word/WPS、干净离线系统、目标用户 | 指定环境/版本及原始结果；缺项不能标为通过 |

常规检查：`PATH="$HOME/go/bin:$PATH" wails3 task check`、`npm --prefix frontend test`、`npm --prefix frontend run build`、`wails3 task build:cli`，后续增加真实协议、集成与格式验证任务。构建和打包分别验证，不把旧 .app 当作新源码产物。测试失败时保留状态并修复后复验；不以更改预期掩盖实现缺陷。

## 证据与完成规则

每份验证记录给出命令、源码版本/差异、组件版本与摘要、输入生成或授权来源、环境、执行结果、限制和复现步骤。`evidence.json` 中 verified 必须对应实际证据；implemented 只代表实现存在，partial 与 blocked 明确记录尚缺项。文档中的性能数值目前是目标值，未测量前不能写入“已达到”。

不会自动调整需求、降低安全/质量标准或自行缩小主场景。遇到设计冲突、关键原型失败、缺失实机/凭据/授权数据等影响关口的情况，停止受影响步骤并请求决定，独立工作继续；目标保持未完成。
