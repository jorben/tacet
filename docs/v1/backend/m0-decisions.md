## 已记录的偏离

- CSV 使用自研字节级扫描器，而不是架构 7 节写的标准库 `csv`：标准库不提供单元格字节位置，经 `csv.writer` 回写会改变未命中单元格的引号与换行。以标准库 strict 模式差分验证解析结果；如需恢复为标准库方案，须接受未命中单元格的字节级变化并重新评估需求 6.3 节的保持要求。

## 数据库选型决定（2026-10-31，task-3）

选定 `ncruces/go-sqlite3` + Adiantum VFS，实现于 `store.OpenEncrypted`。理由：该依赖已在生产模块中；数据库路径无需 cgo，macOS 与 Windows 构建一致；没有 SQLCipher 的加密库打包与界面署名要求；已有十万候选写入、分页分组与错误密钥实测（storage-comparison.md）。代价（架构 5.1 已列出）：Adiantum 只保密、不检测页被篡改，因此备份与迁移前备份需要另外的完整性措施（未做）；SQLCipher 的页级 HMAC 是其优势，若后续需求要求数据库篡改检测，须重新评估。新增 `golang.org/x/crypto` 与 `lukechampine.com/adiantum` 为间接依赖，均从本地模块缓存解析，未联网。

本机验证（macOS arm64，Go 集成）：主库、WAL、SHM 扫描不含原文标记与明文 SQLite 头；检查点与关闭后同样；同密钥重开数据完整；错误密钥、全零密钥与明文库在打开时即被拒绝；错误信息不含 PRAGMA 与密钥；密钥长度与相对路径被拒绝且不创建文件；迁移与回滚在加密库上可用；连接固定 `temp_store=MEMORY`、`secure_delete=ON`、WAL、外键。

局限：SHM 不含标记不等于其内容被加密，其索引元数据的保护未评审；`temp_store=MEMORY` 使大查询占用内存，未在 R1 8 GiB 上测大排序；Windows 上的 WAL、性能与临时文件覆盖未实测；密钥通过 `PRAGMA hexkey` 传入，库内部与 Go 运行时的密钥副本无法保证清零；未在崩溃（断电式中断）后验证 WAL 恢复。

迁移前备份（`store.FileBackup`）：检查点后复制主库密文，附带以数据库密钥派生的 HMAC-SHA256（弥补 Adiantum 不检测篡改）；恢复先校验 HMAC，再关闭连接、写临时文件并原子重命名、清除旧 WAL/SHM，随后调用方须重新打开；成功迁移后丢弃；已有遗留备份时拒绝新备份。测试：迁移失败后原数据保留且无备份残留、无明文；成功迁移不留备份；篡改一位密文或缺失 MAC 时不替换数据库且原连接仍可用；MAC 随密钥变化；密钥长度非法被拒。变异：去掉 MAC 校验、去掉遗留检查、恢复前不关闭连接，均被抓住。局限：未测进程在备份或恢复中途崩溃；遗留备份的启动时处理未实现（当前只是拒绝新备份）；“恢复后清除 WAL”无测试覆盖（无法构造关闭连接后仍留有 WAL 的情形）；备份副本与原库同密钥，没有独立的备份密钥。
